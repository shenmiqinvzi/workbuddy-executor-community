# vNext 行为验收场景

以下为完整vNext的目标验收要求，不表示全表已通过。基础执行链路已有部分自动和本机真实证据，当前覆盖与未验证项见[开发进度](PROGRESS.md)。自动测试可使用适配器替身注入故障；涉及原生行为的结论须另附脱敏的真实桌面证据。检查动作与文件结果，不只匹配提示文字。

| 编号 | 场景 | 必须观察到的结果 |
|---|---|---|
| V01 | 正常修复和必需测试 | 身份、范围正确，停止确认，独立验收后才 accepted |
| V02 | 原生输入等待，详情可用/未知 | 准确显示处理位置或未知；不代批、不重派，期限不延长 |
| V03 | 报告先到、原生仍忙 | 等待停止，accept/rework/new dispatch 均被程序拒绝 |
| V04 | 已取消、停止不明或忙碌会话 | 不恢复已取消任务，不误停其他会话，不释放不确定容量 |
| V05 | 截止后恢复连接及迟到报告 | 原期限和终态保留，迟到报告不可验收，发生与观察时间分开 |
| V06 | 同键重试、不同约定及双进程请求 | 原生只派一次，冲突可解释，结果不明不换键重派 |
| V07 | 文件越界、额外 metadata、用户旧修改 | 本程序处理的越界操作被拒绝，已观测的原生越界交付不能验收；覆盖范围明确，不吞掉旧改动 |
| V08 | 检查后源码改变或旧轮次验收 | EVIDENCE_STALE/STALE_ATTEMPT，没有虚假通过 |
| V09 | 内容正确、表现形式不同 | 按原约定进行语义审查；checker_error 不归 worker 内容失败 |
| V10 | 三轮耗尽、模型未知或不免费 | 无第四次派发、无付费回退、无 UI 绕过路径 |
| V11 | 浏览器刷新、掉线和旧 revision | 恢复原任务，不重复动作，前后端一致 |
| V12 | 数值缺失、重复事件、人工请求/回复 | null 保留，事件不重复计数，人工 episode 和返工/恢复可复算 |
| V13 | Windows 安装、构建及版本切换 | 按 Windows 文档验收；新运行哈希可核对，旧任务不被重放；配置/历史保留，卸载可恢复原技能 |
| V14 | Windows 路径、进程与服务差异 | 记录系统/架构及 WorkBuddy 版本；中文/空格目录、进程归属、真实领取、停止、返工、取消和重连均有证据；服务失败不绕过共用约束 |
| V15 | 第二台 Windows 实机复现与证据分类 | 本机隔离、CI、真实桌面与第二台物理机器分别报告；同一人操作两台机器须如实标记，不冒充独立操作者复现 |

依据：[总体设计](DEVELOPMENT_DESIGN.md)、[接口契约](INTERFACE_CONTRACT.md)。相关 PR 说明实际覆盖的场景、验证方法与未覆盖部分。

## 2026-10-20 覆盖说明

- 本机正常小代码任务已有真实领取、实施、保护测试核对、独立复测和accepted证据；这是V01的基础链路样本，不表示完整vNext范围检查器已实现。

- 完整跨入口并发排他、自动范围保护与指标尚待补齐；第二台物理Windows验收仍由[Issue #3](https://github.com/shenmiqinvzi/workbuddy-executor-community/issues/3)跟踪。
