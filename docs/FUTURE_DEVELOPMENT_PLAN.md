# 后续开发任务与完整愿景交付规划

制定日期：2026-11-04。规划基线：`5f8620e`（`feat/t7d-p05-uncertainty-fence`）。

**本文件是后续开发任务总表，自本轮规划起用于安排开发顺序、核对进度和判定阶段交付。** 下表任务均为待完成的工作，不代表已经实现、验收或部署。已有能力应复用；历史证据可以在确认适用版本和范围后引用，不要求把整个项目重新实现一遍。

完整目标是 Codex 主导的 Windows 本地开发协作工作台：统一协调 WorkBuddy 与 DSH，支持手动、推荐、预授权自动协作，展示可信的模型与额度信息，提供独立验收、任务计量、项目预设及可复现安装。

## 1. 依据、状态与范围

本表落实[总体设计](DEVELOPMENT_DESIGN.md)、[协作设计](COLLABORATION_DESIGN.md)和[路线图](../ROADMAP.md)。功能语义仍以[接口契约](INTERFACE_CONTRACT.md)、[验收场景](ACCEPTANCE.md)及后续明确记录的契约修订为准；本文不豁免既有 P0 门槛。[PROGRESS.md](PROGRESS.md)保存实际进展与证据，本文件保存待办及其状态，两者通过任务编号关联。

基线已经具备共享任务服务、两执行器适配、持久操作与单任务容量、文件范围保护、不可变独立审查及桌面手动控制。已保存的 WorkBuddy/DSH 真实样本证明了部分链路；2026-11-04 DSH 样本没有命令或语义必需检查，且走本机应用服务，不能替代当前安装技能/MCP 的完整代码任务验收。模型、额度、自动模式、统计和异机能力的缺口分别在下表补齐。

当前安装技能已同步到本轮基线；生产面板仍需部署并复验认证显示修复。源码、发布包、安装副本、运行进程的状态分别登记，不用其中一项推断其他项。

首期固定边界：Windows、本地单用户、同一共享网关容量为 1。跨执行器中途交接、安全并行、自动合并冲突、云端团队、多租户和账号托管不进入本轮任务。范围保护不宣称是完整操作系统沙箱；代理模型观察不宣称核实了代理背后的物理模型。

本规划授权的是开发方向；真实模型验证、已有安装修改、推送、合并和发布分别依已有授权办理。新模型任务仍须明确执行器、来源、精确模型、推理档位、已知费用、范围和预算；计划本身不预选模型、不转移旧任务授权，也不放宽既有部署政策。

## 4. 进度更新与每轮交付

任务状态统一使用：`待开始`、`进行中`、`待外部条件`、`待验收`、`已完成`。开始工作时更新状态并登记任务编号；需要修正时回到进行中，保留失败记录。已有历史实现不重复计为本轮新增进度。

每项任务在 PROGRESS.md 按编号追加以下记录：

| 字段 | 必填内容 |
|---|---|
| 任务与范围 | 本表编号、目标、可改范围、实际实现与必要假设 |
| 版本 | 起始/交付提交；若改动未提交则明确；部署和运行版本另记 |
| 验证 | 命令、退出码、实际结果、证据位置及源码/替身/实窗/真实模型/异机分类 |
| 状态 | 已实现、已验证、已合入、已部署分别写明；失败、阻塞与未覆盖不得省略 |
| 下一步 | 剩余动作、依赖、需要的用户选择或外部环境，以及下一项任务编号 |

仅当本任务的交付物与验收证据齐备，才标为已完成；涉及真实闭环或部署的任务不能只凭源码和测试标为完成。开发完成但未取得真实环境条件时，保留实现成果并标待外部条件/待验收，不反复重派相同验证任务。

每轮先推进一个可独立验收的任务。任务涉及实现与部署时可分提交、分证据办理，不把未授权的部署混入源码修改。进度以任务和阶段验收为准，不以提交数、测试条数或未经验证的百分比衡量；没有工期基线时不编造完成日期。

后续聊天、DSH 交接和 PR 描述均引用任务编号及相关验收项。改变范围、顺序或完成条件时记录日期、理由和影响，不能只在聊天中口头跳过未完成项。
