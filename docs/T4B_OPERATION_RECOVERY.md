# T4B：原操作恢复与人工关闭

基线为已验收 T4A `dc20ab9`。本设计先于实现固定；最初源码阶段仅交付 T4B，不扩展 T5–T7，使用隔离原生替身验证。后续在用户另行授权安装、逐任务实际选模和恢复确认后完成本机真实补验，见 [2026-10-27 脱敏摘要](T4B_LIVE_ACCEPTANCE_2026-10-27.md)；不表示所有真实故障或发布均已验收。

## 恢复语义

恢复查询只读原操作、当前 task/attempt、原队列或 DSH 回执及恢复审计；不调用模型、不自动同步或重发。显式 observe 动作可以沿原绑定收集报告/停止事件，仍不准备模型、不派工。未知、idle、超时、找不到回执和客户端提供的 approved/stopped 均不是未执行证明。

人工动作只有两类：`reconcile` 根据原队列的完整持久 enqueue 回执，或已认证的原 DSH 请求事件，解除操作结果不明（不释放工作流容量）；`close` 以匹配身份的原生停止证据，或持久记录明确证明未进入派工的准备阶段，结束原工作流并释放容量。关闭不等于 accepted，不创建成功报告、停止证明或新 attempt。没有充分证明时拒绝，原操作与占用保持。

每次动作必须有新的稳定 operationId、目标 operationId、原操作快照 token、task revision/attempt、原因，以及绑定全部参数的可信本地人工授权。重放先于版本检查，变参同键冲突；不同连接同时决定只有一个获胜。决定、审计、任务关闭事件和容量释放同一 SQLite 事务提交，失败整体回滚。

## 副作用与围栏

新操作保存阶段版本、进入派工标记和完整准备返回回执。无 attempt 的准备未开始或已完整返回、且派工从未进入时，可原子关闭；已存在的历史 attempt 不能借“新返工尚未派工”豁免停止检查。T4A 历史操作缺少这些证明时不能凭缺字段推断未执行。关闭围栏永久绑定原 task，不复用其身份。关闭之后，原异步调用或重启残留不得创建任务、换轮次、取得容量、进入原生副作用或重新打开工作流。

回执恢复只解除原操作的阻塞；不修改原请求、模型、会话、执行器、预算和期限。原调用已有保存结果时继续返回原结果；不确定操作已被处置时返回明确的 OPERATION_RESOLVED 与审计，不把恢复决定伪装成原发送成功。原记录保留，恢复决定另存不可变审计。

## 入口与授权

提供 SDK 的可信应用授权入口和本地恢复命令行：先列出原绑定、证据、影响与版本，再要求键入本次操作标识确认；非交互命令不能用布尔标志代替确认。MCP 只开放恢复查询与显式原绑定观察，不开放人工授权或关闭。现有 HTTP 保持只读；完整 Web 写界面仍按 T7 单独验收。本阶段的操作界面为命令行。

原生观察复用 WB/DSH 协调器原身份的同步能力；不依赖新模型选择，不调用 setModel、createWorker、prompt 或 wake。无法认证的历史原生准备、缺失回执及停止不明仍需外部排障，不能以“人工恢复”绕过 T4A。

## 固定验收

1. 读取零任务/操作/证据写入、零原生调用；显式观察无派工/模型配置。
2. 原队列完整回执或 DSH 请求层证据可恢复；半写文件、错身份、旧 attempt、篡改请求及只有 idle 均拒绝。
3. 停止未证实、历史准备无阶段证明、仍有未解决队列回执时不能关闭或释放。
4. 准备前或完整准备后且从未派工的原操作可关闭，无虚构 attempt/停止；关闭不接受交付。
5. 双连接、同键重复、变参冲突、旧 revision/attempt/操作 token 与确认后状态变化均拒绝或重放原决定。
6. 审计/关闭/释放事务回滚；关闭后原在途异步调用及新请求不能复活原工作流。
7. 恢复后原模型/会话/来源/预算/期限及旧失败记录保持；needs_review 仍占容量。
8. 本地交互确认绑定完整参数，非交互及伪造 approved/stopped 不能授权；HTTP 无新写路由。

使用隔离 SQLite、原生替身、双连接与必要子进程；分别保存基线缺口、修复及独立验证。完成构建、产物一致性、类型检查、旧政策及执行回归、快照、生产依赖干净检出和远端 Windows CI，再交付。

命令与证据说明见[本地恢复控制台](../gateway/docs/OPERATION_RECOVERY.md)。恢复授权五分钟有效，并绑定完整请求；修改任何预期 token 或原因需重新确认。HTTP 不新增写路由；恢复后仍不按第四轮、改模型或最终 accepted 绕过既有准入。
