# T7A：真实只读任务工作台

T7A 在现有 Workbench HTTP 进程内提供本地任务面板，默认读取该进程已打开的 TaskStore 与已存证据。原 stage-2 DTO 不改语义；它缺失的标题、报告和检查不会被前端补造。T7A 新增独立版本的 `panel-1` 展示视图，沿用相同的只读投影、报告认证和已存范围事实。没有派工、模型准备、原生同步、独立命令执行或验收写入口。

## 启动和访问

使用当前源码或包含静态资源的发布包，在 gateway 目录执行：

```powershell
npm ci
npm run build
npm run workbench
```

浏览器打开 `http://127.0.0.1:18493/workbench/`。端口使用现有 `WORKBUDDY_WORKBENCH_PORT` 配置，数据源使用该网关进程的 `WORKBUDDY_DB_FILE` 与 `WORKBUDDY_RUNS_DIR`。构建或打开页面不会启动执行器。TaskStore 的进程启动/初始化与 HTTP GET 的零写入语义分别看待；GET 本身不创建数据库、迁移或写记录。

没有任务时，真实模式显示空工作区。侧栏“数据来源”可以主动切换到持续标记的演示数据；`/workbench/?demo=1` 也明确进入合成演示。模拟正常、十种状态、空列表、读取错误、旧快照、历史缺证、矛盾停止证据和长报告均可查看。演示不代表原生执行，真实连接失败不会自动切换演示。

## 已实现的用户行为

- 列表和详情、任务/目标/标识搜索、状态和工作区筛选、待处理与验收记录视图。数量来自已加载行，筛选范围明确为已加载记录，稳定游标加载更多，不冒称全库计量。
- 分别显示执行报告、原生停止和独立验收。已验收的历史记录缺少 T6 review 时保持原业务状态，但不补造审查凭证。
- 展示当前轮次的最新不可变 review、必需检查来源与状态、证据引用及完整已提供的审查历史。unknown 和 checker_error 不显示成通过，worker 来源不计为独立验收。
- 报告正文只作文本显示；历史审查和技术详情可展开，标识可复制。文件路径不构造本机打开、下载或系统命令。
- 读取已存范围检查和事件，保留跨轮次历史，区分事件发生和稍后观测；新事件不自动改写任务状态。
- 手动刷新、逐项读取失败、旧快照保留、来源切换隔离、请求取消与并发响应身份防护。网络超时有界。
- 桌面主从双栏、平板收起导航、窄屏一次展示一个区域并可返回列表；键盘搜索、方向键切换页签和可见焦点。

## 只读接口与数据含义

| GET 路径 | 返回事实 |
|---|---|
| `/workbench/` 及固定资源路径 | 打包的 HTML、ES modules、CSS 和字体 |
| `/workbench/v1/panel/tasks?limit=50&afterTaskId=...` | `workbuddy-executor/panel-1`；稳定游标列表，单项错误保留 |
| `/workbench/v1/panel/tasks/:taskId` | 相同版本；已存任务和同一 revision 的审查摘要 |
| `/workbench/v1/tasks/:taskId/events` | 继续使用 T2 的跨轮次事件接口 |
| `/workbench/v1/health` | 继续使用 stage-2 的网关进程事实，不冒称执行器在线 |

panel 记录包含 `view`（原 stage-2）、`presentation`（原约定标题、原目标、许可范围、原约定模型、详情报告）、`reviews`（仅详情）和 `reviewMeaning=stored_acceptance_snapshot`。列表不携带报告/审查正文。标题只取已验证原约定，旧任务没有标题时明确“未命名任务”，不把 objective 偷换为 title。

详情仅返回最近 50 份已存审查，超过时显式标记；报告超过 64,000 字符也明确标记截断。检查仅公开必要字段、证据引用和文件数量，不把独立检查内部绝对文件路径映射为下载。记录完整性错误返回 unavailable，不折叠成空历史。读取审查前后再次比对 task revision/attempt，竞争返回 READ_CONFLICT；既有只读投影的损坏、证据过期和未知状态继续保留。

审查展示的是保存时的决定，不检查当前工作区、不重新计算证据哈希，也不决定现在能否接受。最终验收继续由 T6 受控服务重新验证。stage-2 的 checks/changes/artifacts 仍保持其原边界，文件库存来自独立的 workspaceScope 扩展。

静态资源只有固定白名单；loopback、Host/Origin 校验在资源和 API 前共同执行，POST 等写方法拒绝。CSP 仅允许同源脚本、样式、字体和连接，禁止框架嵌入、表单提交及任意 inline script。字体本地打包、附 OFL 许可证；面板无第三方运行时请求。

## 设计与验证归属

视觉方向参照 [taste-skill](https://github.com/Leonxlnx/taste-skill) 的 app screens 流程，使用 framed-sheet（seed 465898610），具体 token、字体、密度和断点见[设计约定](../DESIGN.md)。图标为本项目一致笔画的几何 SVG，字体为 IBM Plex Sans/Mono；没有生成品牌插画或营销图表。

自动回归包括真实临时 SQLite/HTTP、查询零写入、审查完整性与并发拒绝、固定资源白名单/CSP、只读方法和浏览器数据源的语义检查。浏览器检查与真实执行器验收分别登记：读取既有真实任务的独立数据库备份不构成新的模型执行，演示截图也不当作真实执行证据。发布包须包含静态资源和许可证；构建产物及快照通过官方脚本生成。

T7A 不交付手动/推荐/自动调度、权限接管、费用计量、任务写操作、原生深链或正式升级安装；后续阶段另验。全项目状态见[开发进度](PROGRESS.md)。

## 独立桌面入口

在网页界面之上新增 Windows x64 / WebView2 原生窗口，保留现有信息层级。提供单实例、任务链接、桌面私有只读服务、关闭与父进程退出清理、启动失败及重新连接入口。技能源码已加入实际调用时打开窗口的步骤；仅安装或读取技能说明不触发程序。

桌面入口使用独立 SQLite readOnly 连接，不调用 TaskStore 初始化、原生客户端或采集器。公开纯查询实现继续复用，已存 admission、范围和审查的完整性继续检查。构建依赖及预览 ZIP 见 [桌面运行说明](../gateway/docs/WORKBENCH.md)。正常用户目录内的预览安装已通过真实 WebView2 渲染、同窗口任务定位、外部导航和写请求拦截、关闭窗口及自有查看服务退出检查。先使用独立的真实历史备份验证，再只读连接已安装执行网关的数据位置；未新增模型任务，未升级执行桥或修改既有模型规则。低完整性源码目录内直接运行曾失败，原因与正常安装的结果分别保留；异机安装未验收。
