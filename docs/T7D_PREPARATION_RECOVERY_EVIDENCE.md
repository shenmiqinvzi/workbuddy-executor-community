# 不完整原生准备的恢复证据：设计边界

本文件是设计分析，不引入恢复权限，也不证明任何旧任务安全。适用现有 T4B 恢复和人工确认规则。

## 当前事实和缺口

网关在独立 worker 数据库中预留 sessionId，再跨进程调用 WorkBuddy 创建会话。原生调用的异常或超时并不证明请求未到达；进程中断可能发生在发送、创建和写回之间。当前工作流数据库的 preparationEnteredAt、preparationSessionId 与 dispatchEnteredAt 记录网关阶段，不构成原生创建的终止回执。worker 的 uncertain、历史中缺失会话、空闲、文件不变和时间流逝均不能证明没有迟到副作用。两库没有跨原生进程的原子事务。现有桥依次调用 workspace:initialize、session:create 和可选 session:rename；RPC id 是渲染进程内递增值，超时后等待项被删除，迟到响应不会保存为可查询终态。原生数据库只存会话记录，不能由缺失行推断请求已终结。

当前恢复只接受未开始准备或准备完整返回且没有进入派工的无 attempt 阶段证明；否则需匹配的原队列/原生证据。关闭是终态，不授权重派或验收。持久容量必须在证据充分之前保留。

## 可行的未来协议（尚未实现）

需要受信任的原生端提供持久、可查询、绑定原 operationId、taskId、sessionId、规范化 workspace、请求摘要和原生实例/epoch 的创建请求终态：明确拒绝且保证不会再创建，或已创建的完整身份与后续所有原生副作用的终态。单纯客户端捕获的异常、脚本日志或自签名 JSON 不具备这个保证。若原生端不提供可验证的终态和防迟到保证，不能把超时转成安全关闭。

原生端必须先持久登记幂等键，再执行创建；其终态必须在崩溃恢复后仍可查询，保证同键不会重新执行，且拒绝终态之后迟到请求不再产生创建或模型配置。涉及已创建会话时，还需要核验原生全部相关副作用已停止，不能仅靠会话空闲。网关应先持久记录不可更换的请求身份，在同一事务检查任务版本、原操作 token、容量所有者与已有闭合围栏；依可信原生终态和证据摘要产生候选动作，人工确认绑定完整证据，最终事务再次核验版本、证据和容量并写不可变审计、关闭及释放。已有 T4B 围栏仍需覆盖每个后续原生边界；原生端的防迟到保证不可由网关围栏代替。任何证据缺失、冲突、过期、来源不明、其他历史 attempt 或尚在途请求都必须保留占用。

拟议验证应覆盖：原生处理前/后崩溃、回执写入前崩溃、延迟响应和关闭后的迟到创建、网关与原生重启、双进程竞争、两库间故障、身份/epoch/摘要不符、陈旧确认、占用释放事务回滚、重复键及历史记录。必须在可控制的原生替身和实际支持此协议的原生端分别验证；替身测试不构成真实环境证明。
