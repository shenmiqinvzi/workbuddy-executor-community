# T7C：统一日常入口

T7B 已由 PR #20 合入 main `144a520`。T7C 使用该已验证运行代码，把本机技能、主 MCP 和独立桌面工作台接到同一网关、现代任务库与原执行目录。此阶段不改变执行协议或 UI，不新增 HTTP 写入口、调度模式或计量能力。

## 入口与历史

主 MCP 名称保留 `workbuddy`。配置的 command、args、cwd 和显式环境变量指向同一实际安装；旧 `workbuddy_community` 配置保留但设置 `enabled=false`。修改只覆盖这两个服务的目标字段，其他 Codex 设置保持原样。完整配置备份只保存在本机受保护的配置备份目录，不随仓库、发布包或证据摘要分享。

技能入口调用已存在的 `open-workbench-router.mjs`，默认进入现代库。显式声明两个历史库，按真实 taskId 只读定位；未知编号留在现代库显示未找到，重复编号或不可读数据库拒绝路由。历史库不作为派工入口，不迁移或复制现代库及 runs，保留审查、命令证据与原绝对路径绑定。

本机安装原有的精确模型、免费限定及持久政策保持不变。通用仓库仍允许用户明确选择付费或费用未知模型，不能用通用规则放宽已安装部署。每个新协作任务展示真实来源、精确模型、推理档位及已知费率，并取得该任务的实际选择与确认。

安装技能同时修正了旧操作说明：稳定 taskId/operationId 通过 send_task 统一准入后准备原生会话，不单独调用兼容 ensure_workspace；验收使用 check_task、独立检查、review_task 返回的不可变 reviewId 和当前 revision/attempt。旧文本 evidence/artifactPaths 不再提供最终验收通道。备份保留原技能与参考文件，逐项哈希检查后才能回滚；后续编辑冲突会拒绝覆盖。

## 新进程与客户端重连

磁盘配置与当前聊天中的 MCP 进程分别验证。先启动两个真实 SDK stdio 子进程，核对不同 PID、相同运行代码哈希及相同既有任务身份；不以文件保存代替客户端重连结果。

本机随后观察到当前聊天自动加载新主 MCP，旧重复工具连接移除。当前工具返回的 runtime.codeHash 与已验证安装一致，并读取同一现代历史；后续独立文件审查、不可变 review 和最终 accept 均通过该当前聊天连接完成。没有停止 WorkBuddy、清理其他进程或更改全局代理、安全设置。

配置字段、禁用而保留服务与客户端重新加载遵循 [Codex 官方 MCP 文档](https://learn.chatgpt.com/docs/extend/mcp)。若其他机器没有自动重新加载，需要在客户端重启对应 MCP；可用仓库提供的新进程入口恢复原 taskId，不能换键重派。

## 2026-10-31 本机真实补验

以下是新的单次真实样本，不复用 T7B 的任务或模型授权：

| 项目 | 实测结果 |
|---|---|
| 选择 | 用户明确确认 WorkBuddy / local-workbuddy / workbuddy-native，精确模型 `deepseek-v4.1-flash`，原生未提供推理档位 |
| 费率 | 新只读观察为 `x0.00`；实际总费用和模型 API 请求数未知 |
| 原约定 | 独立项目，仅允许改 `src/range.mjs`，只读测试；最多 1 轮、600 秒，不自动续轮 |
| 原始错误 | 闭区间判断错误使用 `value >= min || value <= max`，派工前测试真实失败 |
| 实际交付 | 唯一源码文件改为同时比较上下界；原测试字节哈希不变 |
| 执行来源 | 真实 `desktop_queue` 报告认证、原生 idle 停止证据；1 个 attempt |
| 独立验证 | 原约定精确 JSON CommandSpec，退出码 0，cleanupConfirmed=true；8 项含区间内外、两端点、负区间和单点区间 |
| 独立验收 | 程序来源、范围、命令及原语义项均 passed；当前聊天 MCP 创建不可变 review 并 accept，落库 accepted 与 task_closed |
| 窗口恢复 | 只正常关闭本轮已核对路径的独立工作台，再打开；PID 改变，原 taskId 与已验收状态恢复，没有重新派工 |
| 历史路由 | 现代库 2 项、两个历史库 26 项与 2 项全部按原编号定位；路由检查前后数据库字节不变 |

首次 check_task 在独立命令尚未保存时，原 command 项为 unknown；随后显式执行原命令、创建新的程序检查批次并全部通过。首次记录保留，没有把 worker 自报测试提升为独立命令证据，也没有通过语义检查豁免程序项。

真实 task/attempt/session/review 编号、原始命令日志、配置备份、截图与机器绝对路径仅在本机交付目录保存；本文只提供脱敏归属。历史 blocked/cancelled 不改为成功。空闲时 health 无监听器不代表任务失败；实际执行及停止以本轮认证证据为准。

## 自动验证与边界

新增 `gateway/test/mcp-entry.test.ts` 通过两个真实 MCP stdio 进程和隔离合成任务库，验证重连后身份不变、reviewId/版本参数存在、未选模型拒绝、独立准备拒绝、旧验收参数拒绝且不创建任务或原生配置。它不具备真实原生 profile 或可执行程序，不作为模型补验。该检查进入 Windows CI。

本机 gateway 构建、提交 dist 零差异、该 MCP 检查及三个现有桌面路由测试通过。远端 CI、源码合并与本机配置部署分别登记，不将本机结果写成远端通过。

本次只验证这一台 Windows、一个 WorkBuddy 模型和一个小修复。DSH 新样本、第二台机器、签名发行、安装升级/卸载、自动调度、单任务成本计量未在 T7C 执行；前序环境敏感检查的历史失败记录保留。此阶段没有新发行包，运行代码仍为已验证的 T7B 构建。
