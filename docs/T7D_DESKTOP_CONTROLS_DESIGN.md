# T7D 桌面任务控制：实现约定（进行中）

基线：T7C main `686f557`。用户目标是在独立桌面工作台完成停止、原任务返工和独立验收。沿用现有工作台视觉及桌面原生命令通道。

## 操作与状态

- 停止：显示当前任务和操作后果，提交取消请求；请求成功与原生停止分别展示。停止无法确认时保留原任务，不开放返工或验收。
- 返工：仅在后端确认原生已停止、原任务允许返工且原预算仍有余量时提供。当前契约中的正式取消是终态，不能将“先取消再返工”作为现有能力；对待审查或允许恢复的阻塞任务，在原生停止后沿原任务和原会话输入具体反馈。展示原模型及剩余预算，实际调用必须符合项目对该任务模型选择和授权的要求。结果不明时恢复原操作，不自动重发。
- 独立验收：先显示原约定、实际变更、报告、停止和独立检查的状态；显式运行原约定中可执行的检查，并由独立审查者检查文件、记录具体证据。仅在后端返回通过的不可变 review 后，允许再次确认最终验收。执行器自报不能替代独立检查。
- 重连：任务及操作身份、版本和原生停止证据来自持久事实；窗口关闭或响应丢失不能触发重复操作。历史库只读，缺少所需证据的旧任务显示原因，不补造审查。

## 信任边界

继续使用桌面外壳的精确同源私有命令和原生确认；公共 HTTP 保持只读。动作须复核任务身份、当前 revision、attempt、后端权限、范围和原任务预算，拒绝陈旧或不匹配的请求。固定 action 白名单与有界参数不能演变为任意命令入口；不得将外部页面或浏览器调用提升为本机协调者。

当前 `TaskApplicationService` 的审查操作要求稳定 operationId 和预期版本；取消路径的现有契约与审查/返工不同，应先核对其持久性、并发和不确定结果语义，再设计桌面适配，不能凭界面状态假设操作幂等。返工可能调用模型，必须保留原准入及真实用户授权。

## 验证

先用隔离任务库与假执行器覆盖取消请求与停止未确认、版本竞争、重复提交、原预算耗尽、窗口重开、历史只读、命令输入限制及验收证据绑定。再验证真实独立窗口的键盘操作、窄窗口、错误与恢复状态。真实模型补验另按当前任务实际模型选择与授权执行；源码测试不能替代真实执行。

本文件是开发约定，不表示 T7D 已实现、部署或通过验收。
