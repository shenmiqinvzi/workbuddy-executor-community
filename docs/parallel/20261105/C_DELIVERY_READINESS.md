# C 线开工提示词：D0 收尾与 D1 可执行验收方案

你负责 C 线。先读同目录 COMMON.md，再在 C 工作树执行。目标是补齐可核对的版本/政策/证据账目，并准备两个真实代码样本及验收约定；本轮不实际派工或切换安装。

## D0 任务

1. 完整区分源码、发布副本、已安装技能、磁盘网关、当前 MCP、桌面进程和常驻服务。读取固定的版本/哈希/进程元数据，不导出配置全文、命令行里的凭据或历史正文。读取受限则记录未验证，不推断文件不存在。
2. 只读核对政策的非秘密字段：selectionMode、requireFree、精确模型限定、允许范围、轮次等；记录来源与适用版本，不改政策，不读取账号密钥来证明可用性。
3. 使用已有只读路径。不得用写入式 TaskStore 构造、迁移或修复生产库来采集版本；资源/旧库无法读取时不输出“空闲”。
4. 逐项完善 53 项矩阵的证据位置、归属版本、证据类型、适用范围、状态和剩余动作。旧实机证据不改挂到新候选，合成、真实模型、实窗、CI 与异机分开。
5. 正式发行范围未决定的项写待决定。可以整理分期交付选项与各自门槛，但不能自行把未完成项设为不适用或豁免原 T7D 条件。
6. 对 A/B 最终提交的对齐留待集成后完成，不为等待他们而重复扫描或反复跑当前全量。

## D1 任务

1. 准备 WorkBuddy、DSH 各一个小型真实代码任务方案，含明确文件范围、可复现缺陷、命令检查、语义检查、期限、最多轮次、结果与证据清单。两端任务串行，共享容量仍为 1。
2. 样本应在专用小目录运行，不使用 E:\javaproject 根目录或真实业务项目。提供可重复生成的合成基线，验证检查在修复前会失败，并保护独立验收脚本不被 worker 修改；不要污染生产源码或测试套件。
3. 明确通过“已安装技能 + 当前真实 MCP”执行，不以应用服务直调替代。每个样本记录 task/operation/attempt/session/source/model 的对应，以及认证报告、原生停止、独立检查、不可变 reviewId、accept/closed。
4. 明确原身份返工、领取后取消、重连、输入等待等哪些已有适用证据、哪些另需安排，不把一个正常样本冒充全部异常覆盖。
5. 列出执行前最少条件：A 的可回退候选准备、实际安装授权与版本核对、精确会话就绪、该任务实际执行器/来源/模型/推理/费用选择、容量与原 P0-1 状态确认。
6. 不调用 ensure_workspace、send_task、模型选择/准备、生产登录或实际派工；不自动安装 A 的候选。真实执行授权应在材料具体可审查后集中办理，不要求把凭据发到聊天。

## 交付

验证版本采集的无写入与脱敏边界，验证样本生成器只作用于自有目录及检查的修复前失败；文档不写镜像实现的空测试。已有 1013 项全量证据可以引用其版本，不重跑与本线无关的全套。

提交修订矩阵、D1 方案、样本生成材料及验证结果，清楚区分“准备完成”和“真实执行完成”。最后给出可交给用户审查的条件与操作顺序，不能把 D0/D1 或正式交付宣称全部完成。
