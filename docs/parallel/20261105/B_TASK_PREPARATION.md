# B 线开工提示词：来源诊断与精确会话选择

你负责 B 线。先读同目录 COMMON.md，再在 B 工作树执行。本轮对应 D2-01/02 的一个明确子目标：用户准备任务时能看懂来源/模型/会话为何可选或不可选，并且刷新和故障不会替用户换选择。

## 已有能力和边界

桌面已有项目路径选择、来源/模型/推理选择、DSH 会话选择、任务预览、原生确认、持久回执和资源参考。不要重做整个表单，不新建项目注册系统或执行引擎。

当前 desktopModelCatalog 用 Promise.allSettled 读取 WorkBuddy/DSH，错误主要是通用文字；D2 的全项状态尚未逐项验收。本轮先核对实际缺口，只完善诊断、选择和刷新这一段。保留方案核对、原生确认与共享准入。

## 用户行为目标

1. 区分来源未启用、连接不可用、宿主缺失/不唯一、目录读取失败、私有注册无法核验、没有匹配会话、会话忙碌/不在当前项目、模型被政策禁止等情况。
2. 显示真实已知信息；不能从“在线”推断“可派工/可停止”，无法确认则保留未知。使用已有可核对能力，不为显示状态主动准备模型、激活会话或探测计费模型。
3. 某一来源失败时，保留另一来源成功取得的候选与独立错误；不把部分失败包装为整个目录为空，也不自动换来源。
4. 采用必要的结构化诊断以支持清晰文案，保持既有调用者兼容；不暴露原始异常、路径、认证头或 token。避免为这个子目标新建庞大诊断框架。
5. 刷新目录后，原明确选择仍有效则保留；失效时明确要求重新选择，不默认选第一项、不静默换模型/推理档位/来源。与当前选择对应的费率和政策状态同步更新。
6. DSH 会话只从当前项目、精确 host 的已连接候选中选择；多个候选不选最新，忙碌或不匹配的会话有原因，不自动创建替代会话。
7. 价格未知继续显示可能计费，不推断免费；精确模型、主动免费限定及历史政策不被诊断逻辑放宽。
8. 重叠刷新、换项目、换来源、关闭再打开时，迟到结果不能覆盖当前选择；错误恢复不能恢复另一个项目的旧会话。
9. 错误提示给出可执行下一步，但不会自动登录、安装插件、修改安全设置或运行生产命令。
10. 原确认、回执恢复、效果不明围栏和资源参考仍正常；诊断失败不越权派工，也不新增缺乏政策依据的限制。

## 测试和界面验收

复用现有假目录/假宿主夹具，测试状态区分、单源失败不丢另一源、选择保持/失效、多会话不猜、错项目/忙碌拒绝、未知价格、政策阻止、重叠响应和无模型副作用。只有实际发现的缺口才增加产品代码。

使用现有设计系统；如本环境提供 impeccable，按其流程进行界面修改与验证。对新增状态做定向浏览器和隔离 WebView2 验收，覆盖成功、单源失败、会话歧义、刷新选择失效及窄屏/键盘。使用合成数据，不用真实派工完成 UI 验收。

运行受影响测试、必要构建和类型检查。不得把“测试夹具能选模型”称为真实模型链路通过，不把这一子目标完成标成整个 D2 已完成。
