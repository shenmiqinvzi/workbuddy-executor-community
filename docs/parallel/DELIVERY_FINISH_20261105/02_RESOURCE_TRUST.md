# 02：可信资源来源、路由与故障隔离（第一批）

从G0的L02-resources / feat/finish-l02-resources开发，读COMMON/MASTER及RESOURCE_SOURCE_ROUTING_ACCEPTANCE、RESOURCE_SOURCE_ACCEPTANCE_TOOL、RESOURCE_PLAN_REFERENCE、RESOURCE_FAULT_ISOLATION_ACCEPTANCE。
任务D3-01–04，C08–11/C15，兼顾03请求归因接口。

## 负责范围

拥有resource-routing、plan-resource-reference、quota-observation、资源采集/统计客户端相关模块、workbench/resources*与plan-reference、resource-source-acceptance脚本和定向测试。只改确属资源的模块，实际文件清单开工记录。desktop-dispatch/全局导航/HTTP注册/配置统一入口由集成人接线；不能覆盖01选择流程或03统计服务。

## 实施

1. 复用已有token/积分采集、后台缓存、只读API和验收工具；补齐可部署的固定连接登记、区域/池/模型限制及可解释连接诊断。凭据在受控本机配置入口，浏览器无管理Key，不代理任意URL，不读取现有账号密钥来猜连接。
2. 把连接→池→模型、执行选择声明、实际请求路由的证据分别表示，含来源/观察时间/覆盖/可验证层级与失效规则。同池去重；声明关联不自动升级为实际路由；代理背后模型不可见时保持未知。
3. 为真实联调准备参数校验、仅白名单脱敏报告、只读验证命令和必需条件，能用合成服务重现授权错误/区域错/重复池/时钟缺失。不用真实Key或模型探测填空；真实来源联调转10办理。
4. null、真实零、估算、过期、冷却、触顶依据分别显示，单位不混加。事件/资源故障不改任务状态/来源、不自动停任务；GET零模型请求/零任务写入，后台退避/乱序控制明确。
5. 复用原关联/歧义/区域修复，补真实快照保存/重读链路。接口给05返回参考快照及局限，给03返回可选请求ID/角色/单位/用量层级，缺关联保持null。
6. 不能取得上游请求归因字段时把能力缺口做成明确状态及10待办，不伪造task→模型/额度保证。

## 验收

覆盖认证失败、坏结构、超时、取消、失联、过期/乱序、缓存损坏、重复/歧义声明、区域冲突、共享池、未知时间、null/零、token/积分/货币；两执行器假任务运行中仍可查询监督停止，容量/操作身份不变。
对实际资源视图做浏览器/桌面壳合成展示，接口和缓存哈希可对应，导出不含凭据。复跑已有工具的越界清理/WAL漏检/关闭失败回归。
交源码、专项、固定连接与快照契约、真实联调准备清单；没有真实授权时D3-01/02的实机部分为待外部条件。
