# 07：有明确边界的自动协作源码（第三批）

必须G2完成，从L07-automation / feat/finish-l07-automation开发；读COMMON/MASTER、当前AGENTS、协作/准入/操作恢复/方案契约、05评估与06模板。任务D5-01–03，不允许把“自动”简化为前端定时调用send_task。

## 负责范围

本批核心collaboration、TaskApplicationService、准入/持久操作相关改动与新增automation模块归本线，列出最小实际文件；workbench自动政策视图与派工页面、技能六文件也归本线。统一schema迁移/MCP/HTTP注册由集成人审核接线；08只写独立测试，不改生产代码。所有程序入口复用同一约束。

## 实施

1. 先记录可审查契约/威胁边界：可信用户入口保存政策，精确限定项目/范围/执行器/连接/模型/推理/费用条件/到期/轮次及撤回。agent只能建议不能伪造确认；浏览器不持有管理授权。
2. 政策可查看、修订、到期、撤回，版本/授权来源/审计保留；保留原任务政策及当前部署限制，编辑只影响符合条件的新任务，不修改已派约定或增加旧预算。
3. 持久自动决定绑定任务、方案、政策版本、评估解释与操作意图；执行前事务重验授权/撤回/到期/目录/费用/容量/范围。双进程、重启、撤回竞态、重复触发均至多一次效果，不按TTL释放未知占用。
4. 结果不明只观察原操作，不能新task/会话/来源/模型补发；不在task内换执行器。要求硬费用上限而来源不能保证时拒绝，报价/余额轮询/时限不充当硬限。
5. 界面清楚展示授权内容/当前政策/每次决定/阻塞/撤回，技能说明一致，模板实例不携带有效授权。
6. 默认不启用真实自动派工。开发用合成可信授权对象验证；当前AGENTS逐任务实际选择仍生效。本包不授权改AGENTS放宽，输出将来真正启用的精确政策/信任边界及需要的用户决定；在该决定前真实入口拒绝自动执行。
7. 不扩展为自动提交、推送、部署、原生权限批准、多租户或产品多任务并行。

fake执行器覆盖生效/未确认/过期/撤回/不同项目范围/来源模型漂移/政策变更/历史限制/free-only/费用未知与硬限不支持/预算耗尽/双进程撤回竞态/重启回执/未知准备投递/截止迟到/容量1。
