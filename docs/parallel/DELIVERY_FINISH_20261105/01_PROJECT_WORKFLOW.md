# 01：项目、模型与手动协作流程（第一批）

完整读COMMON/MASTER，必须从G0回执创建的L01-project / feat/finish-l01-project开发。任务D2-01–04，V02/V06/V10/V11、C01–05/C14/C16/C17及对应F项。复用B的诊断/选择刷新，不重写。

## 负责范围

拥有desktop-dispatch*.ts、workbench/dispatch.mjs及本线新增项目/目录视图、相关定向测试、docs/delivery/L01_ACCEPTANCE.md。本批根技能六文件和gateway发布副本也归本线。核心collaboration/task-application-service、统一DB schema、桌面宿主路由入口改动交集成人接线；不改02的资源模块或03统计、04安装模块。

## 实施

1. 做真实路径规范化的项目登记/选择流程，持久选择与项目身份明确，错误、权限、空列表、多候选能理解；不在预览阶段创建原生会话/切模型，不自动选最新会话。目录别名只作提示，不作授权身份。
2. 统一技能/桌面可读的执行器、连接/来源、模型、推理、报价与能力目录；在线、能派工、能停止、未登录/未知分开。单源失败保留另一源，未知状态不升级为空闲。
3. 用户预览完整目标、可写范围、必需命令/语义检查、时限、轮次、费用局限；修改后新revision。可信原生确认沿用现有机制，agent/公共HTTP不能自行确认；过期、确认后改条款、并发消费、同方案不同task不得重复派。
4. direct路径不造原生attempt；明确委派保留用户来源/模型选择。刷新/项目切换/关闭重开/迟到目录响应不覆盖新决定，失效提示重选，不静默回退。
5. 技能与桌面使用同一服务与政策语义，保留原部署/历史政策和逐任务确认；技能说明同步发布副本，不安装到用户技能目录。
6. 输出冻结的项目身份/目录/方案/选择契约给05/06/07，给03提供可关联的非敏感请求标识，不主动改统计实现。需要共享入口按COMMON提供精确接线请求及端到端验证。

## 验收

合成覆盖项目目录错误/歧义/链接身份、无/多/忙/未知会话、单源失败、报价null/零、档位失效、过期/旧revision/双消费、预览零模型准备、direct零attempt。
浏览器和独立正式桌面壳合成路径完成“项目→选择→核对→可信确认→回执/恢复”；记录宿主真假、请求种类、范围与数据未知显示。真实原生目录/派工另归10。
构建、任务视图类型、相关后端与workbench专项、技能六文件一致性；不以测试自建简化页面代替实际视图。
提交代码与HANDOFF，产品未接线时明确待集成人，不能把D2整项直接完成。
