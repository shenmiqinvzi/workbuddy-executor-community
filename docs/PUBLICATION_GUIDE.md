# 公开内容检查

用于准备公开版本和审查贡献，不是“绝对无隐私风险”的保证。提交前由贡献者自查，发布前由维护者复核；模式扫描之外仍须检查上下文。

## 文件与附件

- 公开内容包括代码、通用设计、接口、公开路线图、贡献流程与脱敏评测。
- 个人分工、工时、内部排期、私下授权聊天和联系方式保存在仓库之外；加入 `.gitignore` 不能清除已提交内容。
- 不提交真实 `.env`、凭据、私钥、数据库、应用记忆、会话历史、原始业务日志和本机部署备份。
- 环境样例使用占位符。截图、附件、生成文档和 source map 也检查账号、个人目录、会话标识及业务内容。
- 第三方作者署名与许可声明保留；不能为脱敏抹去来源，也不公开额外的私人沟通资料。

## Git 历史和平台内容

删除当前文件不删除历史。公开前检查所有待发布分支、标签、提交正文、作者/提交者邮箱；同时检查 Issue、PR、评论、附件、Release、构建产物与日志。

如果旧私有历史含内部信息，可保留原仓库私有，另建只含审查后快照的公开仓库。若继续使用原仓库，需先明确历史重写与远端引用清理方案，经所有者确认后执行；不直接切换可见性，也不擅自 force push。

新提交建议使用本人 GitHub noreply 邮箱，避免提交真实邮箱。修改本地 Git 配置不会清除历史邮箱；仓库改回私有也不能收回他人已有副本。

## 可复查结果

记录扫描范围、版本、命中分类、人工核查与已知缺口。详细隐私清单留在私有位置，公开摘要不重复敏感值。准备公开快照时从明确文件清单复制，不打包 `.git` 或本机未跟踪文件；核对文件哈希和公开路径。

检查结束只说明既定范围内的结果。新增贡献、远端新引用或附件后，应检查新增部分。来源与许可状态另外参照 [授权说明](../AUTHORIZATION.md)。
