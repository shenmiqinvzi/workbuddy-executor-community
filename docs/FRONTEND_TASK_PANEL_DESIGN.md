# WorkBuddy Executor：只读任务面板设计与开发任务书

版本：1.0 · 日期：2026-10-20 · 类型：前端共创任务设计，不是已经实现的功能说明。

本任务的核心交付：**不启动 WorkBuddy、不连接真实任务库，也能本地运行并完整演示任务状态的只读页面。**

任务跟踪：[Issue #6](https://github.com/shenmiqinvzi/workbuddy-executor-community/issues/6)。截至2026-10-20本次核对，设计文档已发布、任务已指派，尚未记录实现PR或F01–F20验收；具体负责人和后续进展以Issue/PR为准。全项目阶段状态见[开发进度](PROGRESS.md)。

## 1. 背景与用户目标

目前用户主要通过 Codex 对话了解 WorkBuddy 的任务进度。报告到达、原生停止、独立验收是不同阶段，用户容易把“已回报”理解成“任务已完成”，也难以区分真实执行中与状态尚未确认。

面板要让用户快速回答四个问题：

1. 我正在看哪个项目、哪个任务、哪一轮？
2. 目前执行到哪里？最后一次可靠观察是什么时候？
3. 是否需要我处理？如果需要，去哪里处理？
4. 是否已有结果？结果是否已经独立验收？

使用者以 Windows 本地开发用户为主；无需先理解 UUID、MCP 或原生 RPC 才能看懂页面。界面语言为简体中文，技术代码保留原文。

### 1.1 本期成功标准

- 新使用者通过页面能区分“运行中”“等待输入”“等待停止”“待验收”“已验收”。
- 全部状态与关键异常能通过场景选择器稳定复现。
- 没有真实 WorkBuddy、网关服务或账号时，仍能启动、构建和检查原型。
- 页面数据访问集中在可替换的只读适配层，方便后续接入真实接口。

## 3. 范围与责任边界

### 3.1 必须交付

1. 任务列表与任务详情视图。
2. 全部 10 种目标展示状态，以及加载、空列表、错误、断线、旧数据等界面状态。
3. 模拟数据提供器、场景选择器和确定性的状态流程演示。
4. 项目/状态筛选、标题搜索、只读刷新、任务选择和详情展开。
5. 模拟的报告摘要、检查结果、文件变化和事件时间线。
6. 适合 Windows 桌面浏览器的响应式布局与键盘操作。
7. 最小必要自动检查、人工验收记录和本地运行说明。

### 3.2 本期边界

以下能力留给后续独立任务，本原型不实现其调用入口：

- 创建或重新派发任务、返工、取消、提交审查、最终验收。
- 修改模型、轮次上限、绝对期限、免费模型政策或执行器配置。
- 网页代批 WorkBuddy 权限、模拟原生确认成功、未经验证的打开会话链接。
- 登录系统、多用户角色、云端同步、真实费用统计。
- 修改 gateway 执行内核、SQLite 数据、原生会话、真实 `.env` 或 Codex 配置。
- 接入真实 MCP、现有 `/v1/runs` 或规划中的写接口。

界面可以“选择、搜索、筛选、展开、刷新模拟快照”；这些是展示操作，不改变任务业务状态。首版不放可点击或伪装可用的取消/验收按钮。

## 4. 信息架构与布局

这是帮助用户观察任务的工具界面。优先级是状态清楚、信息稳定、容易定位，不做营销大屏。

### 4.1 页面结构

```text
┌ WorkBuddy Executor ──────────────── [模拟数据] [模拟连接：正常] ┐
│ 场景：报告已到，等待停止  ▾     [重新播放] [刷新模拟快照]       │
├────────────────────────┬───────────────────────────────────┤
│ 任务                    │ 修复计数函数                      │
│ [搜索标题]              │ 示例项目 · 第 2 / 3 轮            │
│ 项目 ▾  状态 ▾          │                                   │
│                        │ 等待停止确认                      │
│ ● 修复计数函数          │ 已收到报告，尚未确认执行完全停止。 │
│   等待停止 · 示例项目   │ 暂时无需操作，请等待确认。         │
│                        │ 最后观测：10 秒前 · 剩余 04:20     │
│ ✓ 修复输入边界          ├───────────────────────────────────┤
│   已验收 · 示例项目     │ 概况 | 报告与检查 | 文件变化 | 事件 │
│                        │                                   │
│                        │ 已完成：修复实现并运行相关测试     │
│                        │ 报告：5 个测试通过，等待独立验收   │
│                        │                                   │
│                        │ [展开技术详情]                    │
└────────────────────────┴───────────────────────────────────┘
```

这是结构线框，不要求逐字符复刻。文案与状态语义必须遵守后文规则。

### 4.2 布局约束

- 桌面宽度不少于 1100px：左侧任务列表约 300–360px，右侧详情自适应。
- 768–1099px：列表约 260px，详情减少并列字段，长内容自然换行。
- 小于 768px：单列，先列表，选择任务后进入详情并提供“返回任务列表”。
- 覆盖 1440×900、1280×720、768×1024、390×844；在 320px 宽度也应可以读取与操作。
- 页面整体不横向滚动；必要的数据表可在自身区域横向滚动。
- 任务切换保持列表筛选条件；刷新不强制跳回第一条任务。
- 不用“总任务/成功率/节省费用”大卡片占据首屏，避免少量模拟数据产生统计幻觉。

## 5. 各区域的具体要求

### 5.1 顶栏与演示工具

- 产品名、持续可见的“模拟数据”标记。
- 模拟连接状态：正常、加载中、连接中断、数据已过期。
- 场景选择器：说明正在预览的异常或流程，不只显示内部编号。
- “刷新模拟快照”：读取同一场景、同一任务的新快照，不新建任务或轮次。
- “重新播放”：只重置当前模拟流程和演示时钟，明确不是重试真实任务。
- 普通页面不展示配置端口、安装路径或凭据输入框。

### 5.2 任务列表

每行显示：标题、项目名、状态文本与图标、最后观测时间；轮次可作为次要信息。

- 按合成数据的 `createdAt + taskId` 稳定排序，默认新任务在前。
- 搜索本期只匹配标题，项目与状态单独筛选；多个条件组合生效。
- 列表中的状态是服务端/fixture 给定的 `displayState`，不从报告文字猜状态。
- 空列表：“暂无任务。本页当前使用模拟数据，可切换场景查看示例。”
- 筛选无结果：“没有匹配的任务”，提供清除筛选，不误报网关故障。
- 长标题在列表中截断，详情可读全文；选择状态有边框/背景与文本提示，不能仅改变颜色。

### 5.3 详情首屏

按以下顺序展示：

1. 标题、项目名、当前轮次。
2. 主状态及一句明确解释。
3. 是否需要用户处理，以及处理位置。
4. 最后观测时间、剩余期限；状态证据未知时直说未知。
5. 任务目标、允许修改范围、最新进展，数据没有提供时展示“暂无信息”。

`remoteStopped` 独立解释为“停止已确认 / 停止尚未确认”，不要把它直接翻译成“任务成功 / 仍在运行”。

### 5.4 概况

- 任务目标与约定范围。
- 当前轮次、轮次上限、原生执行来源。
- 最近进展与阻塞摘要；不提供虚构百分比进度条。
- 用户需要处理时说明到原生界面核对；没有可靠详情时显示“具体请求详情不可用”。

### 5.5 报告与检查

- 真实产品中只展示后端提供的摘要；本期摘要是明确标记的合成内容。
- 有报告但未验收：“已收到执行报告，尚未独立验收”。
- 显示检查名称、种类、状态、检查时间和证据摘要。
- `passed / failed / unknown / not_applicable / checker_error` 分别展示为通过、未通过、未知、不适用、检查器错误。
- 不把 `unknown` 当通过，不把 `checker_error` 解释成 WorkBuddy 修复失败。
- 不根据 exitCode、报告中的“pass”或“已完成”自动更改检查或任务状态。
- 预期超时演练可以显示“实际退出 124（演练预期异常）”；该说明来自样本约定，不意味着任意退出 124 都算成功。
- 报告先用纯文本展示；长内容折叠可展开，原文保留可读，不渲染任意 HTML。

### 5.6 文件变化与产物

- 文件变化展示相对路径、增删改类型、业务文件/元数据/未授权分类，以及检查状态。
- 未授权变化显示明确提醒；原有用户修改冲突与 worker 越界分别说明。
- 缺少文件快照时显示“变更信息不可用”，不能显示“没有改动”。
- 产物显示相对名称、字节数、哈希（可折叠）；字节/哈希未知显示“未知”。
- 首版不提供本机文件打开和真实下载；路径只作为文本，不拼接 `file://` 或系统命令。

### 5.7 事件时间线与技术详情

- 时间线支持按轮次查看，保留前轮失败与返工，不用最后结果覆盖历史。
- 事件发生时间与观测时间分开；默认展示发生时间，明显延迟时补充“稍后观测到”。
- 显示“已回报 → 停止确认 → 独立验收”三个不同节点。
- 技术详情折叠展示 taskId、attemptId、sessionId、revision、原始状态、runtimeSource、观测时间及版本信息（如果提供）。
- 默认操作依靠标题和项目定位，不要求用户复制 UUID。技术标识可以逐项复制。

## 6. 状态与文案规则

下表是目标契约的展示词典，不是让前端自行实现后端状态机：

| displayState | 主文案 | 说明与用户下一步 |
|---|---|---|
| queued | 等待领取 | 已进入队列，等待 WorkBuddy 领取；无需重复提交。 |
| running | 正在执行 | 已领取，展示最近进展与最后观测时间。 |
| waiting_input | 等待你处理 | 去 WorkBuddy 对应会话核对权限或输入；请求详情缺失时明确未知。 |
| waiting_stop | 等待停止确认 | 报告、取消或到期事实已记录，仍待原生停止证据；不提示重新派工。 |
| needs_review | 等待独立验收 | 已收到报告且停止确认，等待 Codex/独立审查。 |
| accepted | 已验收 | 当前交付已独立检查通过；说明这是该次验收快照。 |
| cancelled | 已取消 | 任务已取消；不能把取消当暂停或显示继续执行。 |
| failed | 任务未完成 | 展示后端给出的失败原因，不把所有失败都归为模型内容错误。 |
| expired | 已超过期限 | 期限保留，迟到报告可查阅，不显示为按期成功。 |
| unknown | 状态待核查 | 信息不足，保留最后可靠观测和原因；不自行推断任务停止或失败。 |

补充规则：

- 报告收到但 `remoteStopped=false` 时，不能用绿色“成功”替代等待停止。
- 前端发生断线时，保留最后可靠的 TaskView 并增加“连接中断/仅显示旧快照”提示；不要改写它的业务状态。
- 已验收的历史任务即使目前断线，仍显示最后记录的已验收，同时标记信息未更新。
- 不支持的新枚举按“未知状态，需核查”呈现，保留原值在技术详情，不默认映射为完成。
- fixture 自身互相矛盾，例如 `needs_review` 配 `remoteStopped=false`，应显示“数据不一致，需核查”。不要自动修正原始数据或开放操作。
- 即使 `allowedActions` 出现 accept/cancel，首版仍只读；保留该字段供后续接入，不能因此增加本期写操作。

## 7. 数据分层与接口边界

### 7.1 三层数据

```text
目标 TaskView / Event / Health（传输语义）
                ↓
只读数据提供器 PanelDataSource（本期 Mock 实现）
                ↓
展示适配与组件（格式化、筛选、信息缺失提示）
```

- TaskView 按 [目标契约](INTERFACE_CONTRACT.md)定义，不能拿当前 statusView 直接伪装成完整对象。
- 当前真实接口若将来只能提供部分字段，适配器必须保留未知，不补造验收、成本或事件。
- 状态优先级和操作授权由后端/fixture 决定；展示适配只负责文案、格式与数据质量提示。

### 7.2 只读提供器示意

下面是原型内部接口草案，不是新增网关协议；开发时可以拆分文件，但保持只读能力边界。

```ts
interface PanelDataSource {
  getHealth(signal?: AbortSignal): Promise<HealthView>;
  listTasks(query: ListQuery, signal?: AbortSignal): Promise<TaskPage>;
  getTask(taskId: string, signal?: AbortSignal): Promise<TaskView>;
  listEvents(
    taskId: string,
    afterEventId: number,
    signal?: AbortSignal,
  ): Promise<EventPage>;
}
```

没有 submit/rework/cancel/accept/respond 等方法。场景选择与播放控制放在单独的 `DemoController`，不混入未来 HTTP 数据提供器。

### 7.3 目前尚未定义的展示字段

目标 TaskView 已规定状态、检查、变更、产物、计时等字段，但没有完整定义“目标正文、进度摘要、报告正文和允许修改范围”的传输字段。当前 MCP 的 task/report 也不是规划 TaskView 的同名字段。

原型采用独立的合成补充数据，明确这些字段仍需后端联调确认：

```ts
interface MockPresentationSupplement {
  objective: string | null;
  progressSummary: string | null;
  reportSummary: string | null;
  allowedChangePaths: string[] | null;
}
```

这些不是正式 wire 字段。禁止为了填满页面向 TaskView 随意加字段，再要求后端照着实现。未来可来自显式详情接口或已定义事件 payload，需另开契约变更确认。

### 7.4 以后接入真实数据的范围

后续可替换为 HTTP 提供器，候选只读调用是规划中的 `/workbench/v1/health`、`/tasks`、`/tasks/:taskId` 和 `/tasks/:taskId/events`。目前不编写这些真实请求。

- base URL、认证、Host/Origin 与服务可用性由联调任务确认，不在本期假设端口已启动。
- `capabilities.nativePermissionResponse=false` 时不得呈现网页代批。
- 会话导航在真实能力验证前，不生成 WorkBuddy deep link。
- 当前基础 statusView 缺少完整信息时，可以在未来做诚实降级的兼容适配；本期不接入该兼容层。

## 8. 模拟数据与场景清单

### 8.1 数据约束

- 全部任务、项目名、会话标识、路径、日志均合成；使用 `example-*` 等可识别示例值。
- 不复制本机真实任务库、截图中的会话、凭据、用户目录或运行日志。
- 默认每个场景最多一个未关闭工作流，其余任务为历史。状态图库按场景切换，不暗示执行器能同时运行 10 个任务。
- 场景带固定 `fixtureNow`，例如 `2026-10-20T01:10:00Z`，用于稳定展示倒计时和过期信息。
- 明确区分空数组（已知没有）与 null（未知/尚未观测）。

### 8.2 必做场景

| ID | 场景 | 必须能看见的结果 |
|---|---|---|
| M01 | 正常流程 | queued → running → needs_review → accepted，验收节点独立。 |
| M02 | 报告先到 | running → waiting_stop → needs_review；报告可读但不能提前成功。 |
| M03 | 原生等待，详情可用 | 会话标题、请求摘要与原生界面处理说明。 |
| M04 | 原生等待，详情未知 | “具体请求详情不可用”，不编造权限命令。 |
| M05 | 取消后尚未停止 | waiting_stop，显示请求已记录，仍等待停止。 |
| M06 | 已取消且停止确认 | cancelled，无恢复、重试或继续按钮。 |
| M07 | 到期与迟到报告 | expired 保留；迟到报告只可查阅。 |
| M08 | 明确执行失败 | failed，具体原因与未知项分开。 |
| M09 | 执行状态未知 | unknown，有最后观测时间和核查说明。 |
| M10 | 断线与重连 | 保留旧快照；恢复后仍为同任务同轮次，忽略过期响应。 |
| M11 | 三轮耗尽 | 第 3 / 3 轮，保留历史，不呈现第四轮入口。 |
| M12 | 检查器错误、成本未知 | checker_error 与 unknown 分开；成本/token 未知不显示0。 |
| M13 | 越界文件与用户修改冲突 | 两种原因分开显示，覆盖范围不夸大。 |
| M14 | 空列表、筛选无结果、首次加载 | 三种界面明确区分，可恢复筛选。 |
| M15 | 坏数据与未知新状态 | 缺字段、非法时间、未知枚举/版本、矛盾证据均有可读降级。 |
| M16 | 极端内容与恶意文本 | 长标题、中文/空格文件名、长报告、HTML字符串不破坏页面或执行。 |

M01–M09 合起来必须覆盖全部 10 种 displayState。列表可以添加 100 条合成历史记录，用于滚动和筛选检查。

### 8.3 流程播放

- 静态场景可直接选帧查看；流程场景支持播放、暂停和重置演示。
- 每一帧保存完整、合法的模拟快照，不通过组件内部猜测状态变化。
- 播放顺序、延迟与故障注入可配置并可重现，截图检查使用暂停状态。
- 重置演示时钟只能影响模拟场景，不能修改任务记录中的绝对 deadline。

## 9. 刷新、时间与异常交互

### 9.1 时间

- 数据保留 UTC ISO 字符串，展示按浏览器本地时区，并提供完整时间提示。
- “最后观测”使用后端给定的 `lastObservedAt`，刷新成功时间不能覆盖它。
- “刚刚刷新”与“最后观测”是不同信息，不混成一个“更新时间”。
- 倒计时按 deadline 与统一 Clock 相减；重连、切换页签、刷新不重置期限。
- 到达零显示“期限已到，等待服务端确认状态”，不在浏览器把 running 改成 expired。
- deadline 缺失/非法显示“期限未知”，不显示无限时间或默认30分钟。
- 后台页签恢复时重新按时钟计算，不依赖每秒减1维持正确性。

### 9.2 请求顺序与旧数据

- 对同一读取只保留一个在途刷新，优先完成后再安排下一次，不堆叠请求。
- 场景切换、任务切换与组件卸载时取消旧请求或丢弃旧响应。
- request generation/序号用于判断响应是否属于当前选择，不能按 opaque revision 的字典序判断新旧。
- 任务刷新保持 taskId；新轮次只能来自返回数据，前端不生成 attemptId。
- 事件按同一任务的 eventId 去重，按契约游标分页；不因为换轮次自动清空历史。
- 本期可用3秒的模拟刷新间隔演示，实际网络频率在后续联调时确定。

### 9.3 异常反馈

- 首次失败：错误页/内联错误，提供“重新读取模拟快照”。
- 已有数据后失败：保留内容，标记旧快照与失败原因；不让详情整块消失。
- 合成响应超过15秒没有新观测时，可显示“观测信息较旧”；这是展示阈值，不是业务超时判定。
- 时间缺失时显示“观测时间未知”；绝不以当前时间填充。
- 重连不会自动推进场景到成功，必须取得下一份明确快照。

## 10. 视觉与可访问性要求

视觉定位：克制、清晰的本地工作工具。沿用用户熟悉的列表、详情、标签页与折叠区，首屏重点是当前任务和阻塞说明。

- 浅色主题作为本期必交；深色主题可另作后续增强，不作为本期门槛。
- 使用 Windows 系统字体栈，无需联网下载字体、图标或图片。
- 建议字号：正文14–16px、辅助12–13px、页面/任务标题20–24px；正文可缩放，长报告限制阅读行宽。
- 间距按统一的4/8px刻度组织；采用中性背景、轻边框、单一主强调色。
- 语义颜色只用于状态与提醒；“已验收”才适合明确的成功强调。
- 每种状态都有文字和图标，不能仅凭红黄绿区分。
- 普通文本对比度目标至少4.5:1，大文字至少3:1；焦点必须可见。
- 键盘可完成搜索、筛选、选择任务、切换标签页、展开/复制技术字段和切换场景。
- 交互使用原生按钮/输入语义；标签页采用一致的键盘与焦点行为，不用不可聚焦div充当按钮。
- 动态状态摘要使用适度的 live region；不要每秒朗读倒计时。
- 加载采用布局稳定的骨架；空态、失败态分别设计。
- 遵守 `prefers-reduced-motion`；不做自动滚动事件流、闪烁提醒或装饰性开场动画。
- 200%缩放时主要操作可用；长标识可换行或在局部滚动，不撑坏整个页面。

这些是本任务的设计验收目标，不表示已有界面通过了可访问性认证。

## 13. 验收清单

自动测试聚焦数据与交互风险，不用大量快照测试镜像组件实现。布局、可读性和键盘路径需要实际浏览器检查。

| 编号 | 必验项目 | 通过依据 |
|---|---|---|
| F01 | 环境独立 | WorkBuddy关闭、真实网关未启动时仍能启动mock原型。 |
| F02 | 明确模拟 | 页面各场景与截图持续显示模拟标记。 |
| F03 | 状态覆盖 | 10种displayState全部可选择、文案不混淆。 |
| F04 | 报告不等于完成 | M02先显示报告与等待停止，后显示待验收。 |

| F06 | 原生等待 | 已知/未知详情分别展示，不出现网页代批。 |
| F07 | 取消与到期 | 不出现恢复已取消任务、延长期限或迟到报告成功的误导。 |
| F08 | 原身份恢复 | 刷新/断线恢复仍展示原taskId、attemptId、deadline。 |
| F09 | 旧响应丢弃 | 延迟任务A响应不得覆盖已选择的任务B；换场景同样成立。 |
| F10 | 时间正确 | 固定时钟、零点、后台恢复、非法时间可复现；前端不改业务状态。 |
| F11 | 未知值保留 | null不显示成0；未观测变更不显示“零改动”。 |
