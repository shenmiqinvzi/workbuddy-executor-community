# TEST-GAPS

Three actionable coverage gaps in `src/parse.js` (implementation) vs `test/parse.test.js` (existing tests). All behaviors below were confirmed by running the code; no source or test files were modified.

- **Gap 1 — `parseCount`: non-integer input never reaches the `TypeError` branch.** The guard `if (!Number.isInteger(n)) throw new TypeError('count must be an integer')` at `src/parse.js:3` is never exercised: the only negative-path test, `test/parse.test.js:5`, passes `-1` and asserts `RangeError`, which is thrown by the second guard at `src/parse.js:4`, and no test in `test/parse.test.js` asserts `TypeError` at all. Confirmed actual behavior: `parseCount('3.5')` throws `TypeError: count must be an integer` and `parseCount(undefined)` throws `TypeError` (NaN path). Actionable test: add `assert.throws(() => parseCount('3.5'), TypeError)` and `assert.throws(() => parseCount(undefined), TypeError)` in `test/parse.test.js`.
- **Gap 2 — `parseCount`: blank / `null` input is silently coerced to `0`.** The `Number(value)` coercion at `src/parse.js:2` maps `''` and `null` to `0`, which then passes the integer check at `src/parse.js:3` and the nonnegative check at `src/parse.js:4`, so the function returns `0` instead of rejecting missing input; the only happy-path test, `test/parse.test.js:4`, covers `'4'` and no test feeds an empty string or `null`. Confirmed actual behavior: `parseCount('')` returns `0` and `parseCount(null)` returns `0`. Contract is unresolved — it is not documented whether blank input should be rejected — so the actionable test must pin one reading explicitly: either `assert.equal(parseCount(''), 0)` (documenting the coercion) or `assert.throws(() => parseCount(''), TypeError)` if blank input should be rejected, and either way also cover `parseCount(null)`.
- **Gap 3 — `firstNonEmpty`: the "nothing found" fallback to `null` is untested.** The `?? null` fallback at `src/parse.js:8`, reached when `Array.prototype.find` returns `undefined`, is never executed: the only test, `test/parse.test.js:6`, supplies `[' ', ' hi ']`, a hit on the second element. Confirmed actual behavior: `firstNonEmpty([])` returns `null` and `firstNonEmpty(['  ', '\t', ''])` returns `null`. Actionable test: add `assert.equal(firstNonEmpty([]), null)` and `assert.equal(firstNonEmpty(['  ', '\t', '']), null)` in `test/parse.test.js`.
