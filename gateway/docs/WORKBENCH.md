# 只读任务工作台

此界面与上游 Agent Hub 的 `/v1/runs` 面板分开，读取执行器 TaskStore 已保存的任务、事件与独立审查，不建立另一套执行引擎。

在网关目录安装依赖并构建后，运行：

```powershell
npm run workbench
```

访问 `http://127.0.0.1:18493/workbench/`；端口可由已有的 `WORKBUDDY_WORKBENCH_PORT` 配置指定。数据目录来自同一进程的 `WORKBUDDY_DB_FILE` / `WORKBUDDY_RUNS_DIR`。已安装的旧网关不会因更新源码自动升级，需核对实际运行版本。

默认读取真实保存的记录。数据不足、初次读取失败和未知值保持未知；断线后保留最后快照与原业务状态。数据来源可以显式切换到持续标记的演示样本，连接失败不会自动替换真实数据。演示截图不作为原生执行证据。

报告收到、原生停止与独立验收分别展示。检查和 review 是已存快照，不代表刚刚扫描过当前工作区。历史已验收但缺少 T6 review 的任务不补造检查；unknown、checker_error 和执行器自报不能作为独立通过。

界面可以搜索、筛选、翻页、刷新快照、查看事件、展开报告与复制技术标识；不会派工、返工、取消、接受交付或代批原生权限。网页路径只作文本，不打开本机文件或执行系统命令。字体自托管并附带 OFL 许可证，无外部运行时资源请求。

若资源读取失败，应检查发布包是否包含 `workbench/` 的 HTML、脚本、CSS、字体及许可文件；静态资源使用精确白名单。HTTP 的 loopback/Host/Origin 与只读方法限制继续生效。完整 T7 调度、用户模式、计量与异机部署仍独立验收。
